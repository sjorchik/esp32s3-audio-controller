# Дописати в `docs/history.md` (архів звітів кроків; у промпти НЕ прикріплювати)

Джерело: специфікація MASTER_SPEC_v78 (стан на 2026-10-19). Це звірені планувальником підсумки звітів чатів з кодом P43–P47c, вимірювання власника й рішення; вони винесені зі спеки, щоб не роздувати промпти.

## P43–P47c — перебудова тракту: звіти кроків

**Причина:** не вдалося прибрати перешкоди від аудіочіпів (TDA7318 / PT2313L) — вони лишаються ЛИШЕ як селектор входів.
**Новий тракт:** зовнішній вхід → селектор (TDA7318 / PT2313L) → PCM1808 (АЦП) → ESP32-S3 (цифрова гучність + еквалайзер) → PCM5102 (ЦАП) → підсилювач. Радіо — декодований потік ESP32-audioI2S → ті ж цифрова гучність і EQ → PCM5102.
**Рішення:**
- Селектор: чіп вибирається ПРАПОРЦЕМ ЗБІРКИ між TDA7318 і PT2313L (лише вибір входу). TDA7439 ВІДКЛАДЕНО: це буде інше залізо з іншим дисплеєм, у цій перебудові не беремо. Усі інші налаштування чіпів (гучність, тембр, баланс, gain, loudness) ВИРІЗАЮТЬСЯ.
- З регулювань лишаються ЛИШЕ гучність (цифрова, в ESP32-S3) і еквалайзер. Бас / дискант / баланс / gain / loudness прибираються (прошивка, дисплей, енкодер, IR, веб, API, NVS).
- Еквалайзер діє на ВСІХ входах, пресет ОКРЕМИЙ для кожного входу (замість одного глобального з P30; у міграції старий глобальний пресет копіюється в усі входи).
- Наслідки, які треба врахувати в планах (інваріанти 4, 5, 8, 11 і розділ 14 зміняться): профіль входу = гучність + пресет EQ; хук `audio_process_i2s` обслуговує лише радіо, тож для зовнішніх входів потрібен новий шлях ADC → DSP → I2S TX; NVS blob v5; таблиця IR-дій (BASS_* … GAIN_*) і формат мапи в NVS; спливне вікно P32 і цикл цілі енкодера (P31) спрощуються; сторінки «Аудіо» / «Пульт» / «Налаштування» і `/api/*`.
**СТАН ЗАЛІЗА (відповідь власника 2026-10-19):** вхід підсилювача УЖЕ підключений до виходу PCM5102 (перепаяно); вихід селектора (TDA7318) іде лише в PCM1808; вхід чіпа 0 вільний (Bluetooth-модуль можна підключати). Наслідки для поточного коду (P46b): гучність радіо НЕ керується (повна шкала PCM5102 на підсилювач — до P47a підсилювач тримати на мінімумі), бо `AppController` досі шле гучність на чіп, який підсилювач більше не чує; зовнішні входи ТИХІ, поки `line_path` не інтегровано в `AppController` (працює лише через `lp.*` при `LINE_PATH_ENABLE = 1`); `adc_vu` (VU зовнішніх входів) живий лише при `LINE_PATH_ENABLE = 0`. Тому P47 ділиться на чотири частини, порядок критичний: P47a — цифрова гучність радіо (ВИКОНАНО); P47b — виробничий API `LinePath`; P47c — інтеграція `line_path` в `AppController`; P47d — VU зі `line_path`, видалення `adc_vu`, прибирання «легасі».
**Нумерація входів (РІШЕННЯ власника 2026-10-18):** вхід чіпа, що звільнився (раніше радіо), стає зовнішнім джерелом. Логічний вхід 0 = радіо (цифровий шлях, селектор НЕ задіяний). Зовнішні логічні входи 1–4 відповідають фізичним входам чіпа 0–3 (логічний k → вхід чіпа k − 1). Назви входів, як і раніше, редагуються у вебі; ДЕФОЛТНА назва логічного входу 1 (вхід чіпа 0) — «Bluetooth». TDA7318: радіо + 4 зовнішні (разом 5 логічних входів); PT2313L: радіо + 3 зовнішні (логічний 4 недоступний). Наслідки для P46b (аудит, NVS v6 БЕЗ міграції): `defaults::kInputCount` та маска `inputEnabledMask` розширюються; міграція НЕ потрібна (рішення власника 2026-10-19: прошивки ставляться на СТЕРТИЙ flash, `pio run -t erase`, усі налаштування — дефолти нової версії формату; станції, IR-мапу й Wi-Fi власник налаштовує заново); дефолти: 0 «WiFi Radio», 1 «Bluetooth», 2 «TV Box», 3 «Computer», 4 — додатковий (назва за вибором чату, редагується; вимкнений за замовчуванням), маска дефолтна = входи 0–3 увімкнені; перевірити зворотну залежність: IR-дії прямого вибору входу й збережену мапу пульта, веб-API (`input`, `inputNames`, кількість), екран і колір / іконки входів, цикл перемикання входів кнопками й енкодером. У P44–P46a не торкаємось.
**Результат P43 (аудит/дизайн виконано; рішення нижче — ПРОПОЗИЦІЯ чату з кодом, прийнята за замовчуванням, власник може поправити):**
- Обрано варіант V2: I2S1 duplex slave (RX+TX) на тих самих BCLK GPIO15 / WS GPIO17, що веде I2S0; DOUT GPIO18 мультиплексується між I2S0 (радіо, без змін) і I2S1 TX (зовнішні входи); потрібна ФІКСОВАНА fs (48 кГц) на I2S0 при зовнішніх входах (спосіб фіксації залежить від `Audio.h`/`Audio.cpp` — НЕ перевірено, з’ясовує P44). Запасний варіант V3 (весь звук через I2S1) відкладено. V1 (носій у бібліотеці) відхилено.
- Порядок обробки: EQ (пресет входу) → вимір VU → цифрова гучність (× рівень станції для радіо) → мʼют; плавність гучності всередині `dsp_volume` (фаза Ramp в `AppController` стане зайвою).
- Нова задача `line_path`: ядро 1, лише при зовнішньому вході, блок 128 кадрів (відступ від «ядро 1 лише аудіо» — вирішується за виміром у P44).
- Профіль входу = {volume, eqGainsDb[5]}, NVS blob v5 (міграція v1…v4→v5, глобальний EQ копіюється в усі входи). Чіп селектора — прапорець збірки (`config/selector_config.h`), `processorType` лишається лише в GET. IR: 8 дій BASS_*…GAIN_* зарезервовані в enum (не перенумеровувати), прибрані з навчання; нові дії лише в кінець. XSMT переходить під модуль `dac_output`; мʼют = цифровий + XSMT + STBY.
- Нові файли: `audio/line_path.{h,cpp}` і `config/line_path_config.h` (P44, у коді); ПЛАН, у коді ще нема: `audio/dsp_volume.{h,cpp}`, `audio/dac_output.{h,cpp}`, `config/selector_config.h`; `eq.*` — екземпляри; `adc_vu.*` злити в `line_path` (P47). Рядки розділів 12–14 додаються після виконання кроків.
**P44 ВИКОНАНО, перевірено власником на залізі (прототип `line_path`, `LINE_PATH_ENABLE = 0` за замовчуванням):** I2S1 duplex slave (RX+TX, std 32 біт Philips, BCLK GPIO15 / WS GPIO17 / DIN GPIO8, TX dout не виділений); GPIO18 мультиплексується через `esp_rom_gpio_connect_out_signal` між `I2S0O_SD_OUT_IDX` (радіо) і `I2S1O_SD_OUT_IDX` (прохід) — на залізі радіо працює, перемикання в обидва боки без перезапуску. 48 кГц на I2S0 під час проходу — штатним `Audio::setOutputSampleRate(SR_48000 / SR_ORIGIN)` (через `AudioPlayer::setFixedOutputRate`, виконує задача плеєра лише в Idle), бібліотеку не змінювали. XSMT (GPIO45) під час проходу керує `line_path`. Послідовності: start — XSMT low → `AudioPlayer::stop()` до Idle → drain 600 мс → фіксація fs → GPIO18 на I2S1 → enable RX, TX → `restorePinOutputs()` → відкинути 6 блоків → XSMT high + лінійне наростання 100 мс до −20 дБ; stop — спад 20 мс → XSMT low → 20 мс → disable TX, RX (GPIO18 лишається на I2S1); `returnToRadio()` — (stop) → XSMT low → GPIO18 на I2S0 → `setFixedOutputRate(false)` (XSMT піднімає плеєр, коли радіо стабільне). Аварія: немає блоків ≥ `kStallMs` (300 мс) → XSMT low, стан Stalled, самовідновлення (гілку на залізі НЕ викликали). Діапазон послаблення −60…−6 дБ (типово −20), лише послаблення. Виміряно: ≈45 000 блоків, 3 старти — stalls / readTimeouts / readErrors / writeTimeouts = 0; задача ядро 1, пріоритет 6, стек 5120 Б (вільний мінімум ≈3,2 КБ), блок 128 кадрів (2,7 мс), `maxProcessUs` 48…87, старт ≈0,65 с (600 мс — drain); `rxOverflows` = 8 і `txOverflows` = 30 лише на переходах старт / стоп; затримку проходу не вимірювали (оцінка ≲ 20 мс). Рішення: ядро 1 для `line_path` прийнятне.
**P44b ВИКОНАНО, перевірено власником на залізі (життєвий цикл `line_path`):** `begin()` нічого не виділяє (лише стан, семафор, Serial-тест); у `start()` виділяється буфер блоку й створюється задача, яка першою дією створює канали I2S1 (чекає семафор, `kCreateWaitMs`); у `returnToRadio()` — GPIO18 на I2S0, зняти 48 кГц, знищити канали, звільнити буфер, задача завершується (`stop()` ресурси лишає). Переходи без переповнень: нулі в TX на settle-блоках, вікно мʼюту обслуговується `pump()` (RX вичитується, TX нулі). Невдача після прийнятого запиту → `abortStart()`; нестача памʼяті → `start()` повертає false, `allocFailures++`, XSMT low, GPIO18 лишається на I2S0. `LinePathStats` +`allocFailures`, +`recoveries` (відновлення зі Stalled не входять у `starts`). Тести (`LINE_PATH_TEST`): +`lp.heap` (працює і при `LINE_PATH_ENABLE = 0`), `lp.fault [мс]`, `lp.cycle <N>`. Виміряно: `lp.cycle 20` — PASS: free 95 268 → 95 204 Б (−64 Б одноразово, без росту), largest block 44 020 → 44 020, `rxOvf` / `txOvf` на переходах +0, `allocFailures` = 0; `lp.fault` — PASS (Running → Stalled з мʼютом на 301 мс → самовідновлення, без «повної гучності»). Ресурси проходу ≈ 21,4 КБ внутрішньої RAM (лише під час проходу; DMA лишено 6 × 128, стек 5120 Б). Старт ≈ 646 мс (≈ 800 мс, коли радіо ще грає). Радіо після `lp.radio` грає чисто, SSL піднімається (≈ 343 мс). ВАЖЛИВО (вимір внутрішньої RAM під https-радіо): `LINE_PATH_ENABLE = 0` (теперішня «бойова» збірка, `adc_vu` резидентний) — free = 18 716 Б, largest = 8 180 Б, min free ever = 15 660 Б; `LINE_PATH_ENABLE = 1` (без `adc_vu`, ресурси проходу не створені) — free = 46 532 Б, largest = 31 732 Б. Тобто нинішня збірка вже працює майже на межі RAM, а нова архітектура (злиття `adc_vu` у `line_path`, P47) звільняє ≈ 28 КБ під радіо. Під час `lp.start` з працюючого радіо ресурси створюються ДО зупинки радіо — пікове `min free ever` ≈ 24 356 Б (прийнятно; за потреби переставити «зупинити радіо → створити ресурси» у P47).
**P45 ВИКОНАНО, перевірено власником на залізі (цифри й на слух) (EQ-екземпляри, `dsp_volume`, DSP у `line_path`):** `eq::Processor` — клас-екземпляр (два екземпляри: `g_radio` для радіо, власний для `line_path`, fs 48 кГц); `namespace eq` лишився фасадом над екземпляром радіо з тими самими сигнатурами; `designPeaking` (double) тільки в сеттерах, `process()` без `double` і без мʼютекса (seqlock), коефіцієнти інтерполюються лінійно за `eq_cfg::kCoefRampMs` = 20 мс; DF2T збережено; стан фільтрів скидається при snap (нова fs) і при виході з bypass. `audio/dsp_volume.{h,cpp}`: `DspVolume` (`setAttenuationDb`, `setMute`, `forceMute`, `isRamping`, `isSilent`, `process`; посемпловий ramp, `kRampMs` = 100 вгору, `kMuteRampMs` = 20; float). `line_path`: RX → піки входу (до EQ) → EQ → `dsp_volume` → піки виходу → TX; Stall — `forceMute` + XSMT low; стоп — `setMute(true)` ramp, потім `forceMute`; EQ скидається при старті й після відновлення зі Stalled. `LinePathStats` +`peakOutLeftDbfs`, `peakOutRightDbfs`, `clipCount`. Гучність радіо лишається в TDA7318 (`dsp_volume` для радіо НЕ вмикався). Виміряно: при плаский EQ і `att` −20 дБ вихідний пік = вхідний − 20,0 дБ (−11,1 → −31,1; −17,2 → −37,2); усі 5 смуг +6 дБ → вихід на ≈ +6,1 дБ; `maxProcessUs` 180–195 мкс (плаский EQ) і 395 мкс (5 смуг +6 дБ) при бюджеті ≈ 670 мкс; `clipCount` = 0; `stackFreeMin` 2 988…3 036 Б; `lp.fault` PASS (recoveries = 1); `lp.cycle 20` PASS (free −32 Б одноразово, largest block без змін, на переходах rx / tx +0); радіо з пресетом EQ грає. Слухання власника: «на слух все ок» (клацання при зміні EQ / мʼюті / гучності, шум, звучання радіо на новому EQ — без зауважень); кількісно окремо не вимірювано: приріст окремої смуги на тоні (±0,5 дБ), шумова підлога 60 Гц. Додатково відкрито: `kUnmuteRampMs` / `kMuteRampMs` у `line_path_config.h` — мертві, прибрати при P47; seqlock копіює через `memcpy` (формально гонка даних, на ESP32 працює); не бачено `settings.cpp`, `web_api_player.cpp`, `app_controller.cpp` — повний список викликачів `namespace eq` складається в P46.
**P46a ВИКОНАНО, перевірено власником на залізі (профіль входу {volume, EQ×5}, `AppController` без тембру / gain / loudness):** NVS v5: `InputProfile{ volume, int8_t eqGainsDb[5] }`, `Settings` без глобального `eqGainsDb` (160 Б, blob 164 Б; довжини v1 / v2 / v3 / v4 = 144 / 164 / 168 / 170; довжини v2 і v5 збігаються, тому формат розрізняється за байтом версії + довжиною); `settings_cfg::kFormatVersion = 5`, `kPrev4FormatVersion`. Код міграції v1…v4 → v5 лишився в `load()`, але НА ПРИСТРОЇ НЕ ВИКОРИСТОВУВАВСЯ (власник ставить збірку на стертий flash; хостовий тест міграцій у репозиторій не додано) — буде прибрано в P46b. `AppController`: замість `s_profiles` — `s_volumes[]`, ціль енкодера завжди Volume (короткий клік енкодера = лише вікно гучності), `cycleTarget` / `adjustGain` / gain-hold / P31-таймаут прибрано; на чіп відправляються `app_controller_cfg::kNeutral*` (усі 0; кодування тембру PT2313L не перевірено); `setTone` / `GainSet` приймають і ігнорують; IR-дії BASS_* … GAIN_* ігноруються з логом; `persist()` пише лише гучності профілів; EQ радіо = `profiles[0]` (load, `resetToDefaults`, `/api/eq` при вході 0, `applyRadioEq` при поверненні на вхід 0). `/api/eq` працює з профілем ПОТОЧНОГО входу (`AppState.inputIndex`), форма JSON без змін; `/api/gain` і `bass` / `treble` / `balance` / `loudness` у `/api/settings` приймаються й ігноруються, GET віддає нейтральні 0 / 0 / 0 / false. ПРАВКА ВЛАСНИКА вручну (чат її не бачив і не перевіряв): `net/web_server.cpp` — `handleSettingsGet` більше не читає `pf.bass` / `treble` / `balance` / `loudness`, віддає нейтральні значення.
