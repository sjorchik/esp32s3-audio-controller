## 1. Загальне

Аудіо-контролер: інтернет-радіо + зовнішні аналогові входи, керування кнопками, енкодером та IR-пультом, кольоровий дисплей, веб-інтерфейс налаштувань.

- Збірка: VS Code + PlatformIO, Arduino framework.
- Мова коментарів у коді — українська, ідентифікатори (змінні, функції, файли) — англійська.
- Повідомлення в Serial-логах — англійською, короткі, з тегом модуля, наприклад `[IR] ...`.
- Репозиторій: https://github.com/sjorchik/esp32s3-audio-controller

## 2. ПРАВИЛА ВІДПОВІДІ (обовʼязкові)

1. Завжди видавай ПОВНИЙ текст кожного файлу, який створюється або змінюється. Ніяких фрагментів «встав сюди», «решта без змін», «...».
2. Перед кодом дай список файлів: шлях + «створено» або «змінено».
3. Не змінюй публічні інтерфейси інших модулів. Джерело правди для наявних сигнатур — ПРИКРІПЛЕНІ до цього повідомлення файли з репозиторію, а не переказ у MASTER SPEC. Якщо потрібного файлу не прикріплено, а без нього не обійтись — зупинись і запитай його. Якщо зміну зробити необхідно — явно попередь, опиши зміну і видай повні тексти всіх файлів, яких вона торкається.
4. Усі піни, таймінги, розміри буферів і прапорці — лише через `config/`, без «магічних» чисел у модулях. Існуючі `config/pins.h`, `config/features.h`, `config/defaults.h` НЕ переписуй і не дописуй у них (виняток — коли промпт прямо дозволяє точкову правку): їх значення бери з ПРИКРІПЛЕНИХ файлів (розділ 13 — лише перелік), імена використовуй точно (`pins::kBtnUp`, `ENABLE_VU` тощо). Константи нового модуля клади в НОВИЙ файл `config/<module>_config.h` у тому самому стилі: `constexpr` у власному namespace (`<module>_cfg`), імена `kPascalCase`; лише прапорці умовної компіляції — `#define UPPER_CASE`. Кожен `.h` починається з `#pragma once`.
5. Не роби більше, ніж просить конкретний промпт. Модулі, які не входять у завдання, не реалізуй.
6. Використовуй лише ті версії бібліотек і тулчейн, що вказані в розділі 11. Якщо потрібна інша версія або нова залежність — попередь окремим пунктом і покажи повний фрагмент `platformio.ini` (повний файл).
7. Не використовуй блокуючі `delay()` у задачах, крім явно обґрунтованих випадків. Використовуй FreeRTOS-примітиви (черги, таймери, `vTaskDelay`).
8. Великі структури, спрайти й буфери — у PSRAM (`ps_malloc` або відповідні прапорці бібліотек), а не у внутрішній RAM.
9. IDF 5.x: використовуй ТІЛЬКИ нові драйвери — PCNT (`driver/pulse_cnt.h`), RMT (`driver/rmt_rx.h`, `driver/rmt_tx.h`), LEDC через `ledcAttach()`. Старі API (`driver/pcnt.h`, legacy RMT, `ledcSetup`/`ledcAttachPin`) не використовувати. I2S напряму не чіпати: ним володіє ESP32-audioI2S.
10. Сигнатури заглушок СВОГО модуля (розділ 12) можна змінювати, якщо цього вимагає завдання, але повідом про це окремим пунктом і видай повні `.h`. Заглушки чужих модулів не змінюй.
11. Наприкінці відповіді: розділ «Як перевірити» (що побачу в Serial / на дисплеї / у поведінці пристрою) і розділ «Відомі обмеження».
12. Якщо для завдання бракує відомостей — спочатку постав уточнювальні питання (не більше 3), а не вигадуй припущень мовчки.

## 3. Залізо

- **MCU:** ESP32-S3 N16R8 (16 МБ flash, 8 МБ octal PSRAM). Заборонені піни: GPIO 26–37 (flash/PSRAM), 19/20 (USB).
- **ЦАП:** PCM5102 (I2S). SCK підключений на GND (внутрішній PLL, MCLK не потрібен). XSMT — софт-мʼют, active-low, зовнішній pulldown 10 кОм (при старті пристрій замʼючений). Вихід ЦАПа (≈ 2,1 Vrms при 0 dBFS) іде на вхід підсилювача.
- **АЦП:** модуль PCM1808: MCLK = GPIO16, BCLK = GPIO15 і LRCLK = GPIO17 (ТІ САМІ лінії, що й у PCM5102), DIN = GPIO8; slave-режим (стрепи MD0 = MD1 = FMT = GND: I2S 24 біти, авто MCLK/fs); MCLK/BCLK/LRCLK дає ESP32 (I2S0), захоплення — I2S1 RX slave у `line_path`. ВАЖЛИВО: аналоговий вхід АЦП — безпосередньо від DPDT-реле входів; на вході модуля НЕ має бути ФНЧ «10 кОм + кераміка 220 нФ» (власник його прибрав 2026-10-21: давав fc ≈ 72 Гц, звук «в діжці»); земля джерел, реле й модуля має бути спільною.
- **Входи:** радіо (цифровий шлях, логічний 0) і ДВА зовнішніх (TV Box = 1, Computer = 2), що комутуються ОДНИМ DPDT-реле на одному GPIO (GPIO1, HIGH = Computer, вимкнено = TV Box, пауза контактів 30 мс). Bluetooth і AUX немає. Аудіочіпи TDA7318 / PT2313L ВИРІЗАНО повністю (I2C-шини в проєкті немає).
- **Підсилювач:** окремий, вхід — з PCM5102; керування STBY — GPIO46 (1 = працює).
- **Дисплей:** ST7789 170×320, SPI2 (FSPI, піни IOMUX), горизонтальна орієнтація 320×170. Обовʼязково врахувати зміщення вікна (offset) для панелі 170 пікселів. Підсвітка — LEDC PWM.
- **Керування:** 6 кнопок (POWER, UP, DOWN, LEFT, RIGHT, OK), енкодер з кнопкою (апаратний PCNT), IR-приймач VS1838B (RMT RX, вихід active-low).
- **IR-протокол:** RC5 / RC5X (біт toggle; у RC5X 7-й біт команди береться з інвертованого S2). Кнопки пульта навчаються користувачем (режим навчання), коди зберігаються в NVS.
- **Резерв:** UART1 (TX 42, RX 48) — майбутній Bluetooth-модуль; зараз не використовується.
- **Живлення:** одне джерело 12 В → 5 В, 3.3 В (9 В для аудіопроцесора більше не потрібні).

## 5. Програмна архітектура

**Подієва шина.** Єдина FreeRTOS-черга подій (`EventBus`). Джерела (кнопки, енкодер, IR, веб) → логічні `Action` → `AppController` → модулі. Модулі не викликають один одного напряму для керування, лише через події й `AppState`. Перелік `Action` — `core/events.h`; кожна подія має прапорці `repeat` (утримання), `longPress`, `veryLongPress` (лише POWER) і джерело (`EventSource`).

**Розкладка керування.**

Головний екран (Radio / ExternalInput):
| Дія | Radio | Зовнішній вхід |
|---|---|---|
| UP / DOWN (кнопки) | перемикання логічного входу 0..2 (пропускає вимкнені маскою) | те саме |
| LEFT / RIGHT | перемикання станції | немає дії |
| OK коротко / утримання | play/pause / список станцій | немає дії |
| Енкодер обертання | гучність | те саме |
| Енкодер клік | мʼют (перемикання) | те саме |
| Енкодер утримання | відкрити екран «EQ + баланс» | те саме |
| POWER | standby вкл/викл; утримання ≥ 3 с = «тихий» перезапуск | те саме |

Список станцій (`Mode::Menu` + `MenuContext::StationList`): обертання / UP / DOWN — вибір; OK або клік енкодера — запустити вибрану станцію; BACK — вихід; утримання енкодера — мʼют.

Екран «EQ + баланс» (`Mode::Menu` + `MenuContext::EqBalance`): 6 вертикальних стовпчиків — 5 смуг EQ (`eq_cfg::kBandFreqHz`, ±12 дБ) і Bal (±20 дБ) АКТИВНОГО входу. Клік енкодера і `RIGHT` — наступний параметр по колу (60 → 250 → 1k → 4k → 12k → Bal → 60), `LEFT` — попередній; `UP` / `DOWN` (з повтором) і обертання (лише знак) — ±1 дБ; вихід — утримання енкодера, BACK або 10 с без дій (`eq_screen_cfg::kTimeoutMs`); закривається при standby, OTA, початку навчання IR, зміні входу з будь-якого джерела, підніманні AP, веб-командах станцій. `VOL_UP` / `VOL_DOWN` працюють, `INPUT_*` міняють вхід (і закривають екран). Зміни застосовуються наживо й зберігаються в профілі входу.

Спливне вікно з великими цифрами (`FontSize::Digits`; гучність і баланс): гасне за `kPopupTimeoutMs` = 5 с або одразу від натискання будь-якої кнопки / кліку енкодера / кнопки IR, КРІМ `ENC_CW` / `ENC_CCW`, `VOL_UP` / `VOL_DOWN`, `BALANCE_UP` / `BALANCE_DOWN` (вони показують / продовжують вікно); механізм — `AppStateData::popupDismissed` (рівень).

IR-пульт: OK і BACK навчаються, `ENC_*` ні. Прямий вибір входу — `INPUT_RADIO` / `INPUT_TV` / `INPUT_PC` → 0 / 1 / 2 (`INPUT_AUX` без дії); `BALANCE_UP` / `BALANCE_DOWN` — ±1 дБ балансу активного входу; 6 дій `BASS_*`, `TREBLE_*`, `GAIN_*` зарезервовані в `enum` і ігноруються (з навчання виключено, `learnable = false`; `INPUT_AUX` теж).

**Узгоджена поведінка переходів.**
- **POWER (standby):** вхід у standby зупиняє `AudioPlayer`, мʼютить звук і виводить підсилювач у STBY. Вихід відновлює той самий режим / вхід / станцію (`Settings.lastInput` / `lastStation`). Після ХОЛОДНОГО старту (`ESP_RST_POWERON` / `ESP_RST_BROWNOUT`) пристрій стартує в standby; інші перезапуски — як раніше. Якщо `lastInput` вимкнений маскою — вмикається радіо.
- **Зміна входу:** профіль входу (гучність, EQ, баланс) застосовується ПІД мʼютом; радіо ↔ зовнішній і вхід ↔ вхід — за автоматом `line_path` (див. розділ 11).
- **Перезапуск:** усі програмні перезапуски (веб `reboot` / `factory-reset` / `wifi/reset`, успішне OTA, портал Wi-Fi, утримання POWER) проходять через «тихий» шлях: цифровий мʼют → підсилювач у STBY → пауза → `ESP.restart()` (`AppController::prepareForRestart()` або `restartService()`).

**AppState.** Єдине сховище стану: режим, поточний вхід, гучність, баланс, EQ екрана, мʼют, індекс станції, метадані, статус Wi-Fi / потоку, рівні VU, стан спливного вікна. Доступ потокобезпечний.

**Режими:** `Standby`, `Radio`, `ExternalInput`, `Menu` (контексти: `StationList`, `EqBalance`), `IrLearn`, `WifiSetup`, `OtaUpdate`.

**Задачі FreeRTOS.** Аудіо — окреме ядро від UI і мережі. UI малює зі спрайту (double buffering у PSRAM), без блокувань аудіо. Ядра й пріоритети задач — константи в config.

**Ядра й пріоритети задач (фіксовано):**
- Ядро 0: введення (кнопки, енкодер, IR), AppController, UI/дисплей, Wi-Fi, веб-сервер.
- Ядро 1: аудіо (ESP32-audioI2S, декодування, I2S; задача `line_path` — пріоритет 6). На ядрі 1, крім аудіозадач, нічого не запускати; Arduino `loopTask` там теж є (пріоритет 1), `loop()` лишається порожнім.
- Зайняті пріоритети (ядро 0): введення = 4 (`input_cfg::kBtnTaskPriority` / `kEncTaskPriority`). AppController — нижче за 4, вище за UI (орієнтовно 3); UI — орієнтовно 2; мережа / веб — найнижчий (орієнтовно 1). Аудіо — вище за 4.
- Кожна задача періодично віддає процесор (vTaskDelay / блокуюче очікування черги); задачі не мають годувати watchdog вручну.

**Збереження.** Налаштування — NVS (namespace `audioctl`). Станції, шрифти, іконки — LittleFS; веб-сторінки вбудовані у прошивку.

**Флеш 16 МБ.** Таблиця розділів (`partitions.csv`): `nvs` 0x9000 + 0x5000, `otadata` 0xE000 + 0x2000, (вільно 0x10000–0x1FFFF), `app0` 0x20000 + 0x580000, `app1` 0x5A0000 + 0x580000, `spiffs` (LittleFS) 0xB20000 + 0x4E0000; кінець 0x1000000. Збірка PlatformIO / pioarduino пише `boot_app0.bin` за ФІКСОВАНОЮ адресою 0xE000 незалежно від `partitions.csv`, тому `otadata` ОБОВʼЯЗКОВО має покривати 0xE000..0xFFFF; не переміщувати без перевірки логу `pio run -t upload -v`. Процедури прошивки, міграції й відновлення — `docs/flashing.md`. Board: `esp32-s3-devkitc-1`, `board_build.arduino.memory_type = qio_opi`, консоль на UART0.

## 8. Wi-Fi provisioning

- Немає збереженої мережі або 3 невдалих спроби підключення → режим AP з назвою `AudioCtrl-Setup`, captive portal (DNS), сторінка: скан мереж, вибір, пароль → збереження в NVS → перезапуск у режим STA.
- На дисплеї в цей час — інструкція (назва AP, адреса).
- Скидання Wi-Fi — утримання кнопки OK під час старту.
- (P28) Поки піднята AP (на БУДЬ-ЯКОМУ вході) — `Mode::WifiSetup`: екран налаштування «Setup Wi-Fi» з підказкою «OK: work offline», звук замʼючено, реагують лише POWER (standby; утримання ≥ 3 с = перезапуск) і коротке OK / клік енкодера. OK = офлайн-режим: Wi-Fi вимкнено (`WiFi.mode(WIFI_OFF)`, AP / портал / веб-сервер / mDNS зупинені), усі входи, крім радіо; режим не зберігається в NVS, вихід — перезапуск (утримання POWER або живлення). До підняття AP (спроби STA ≈ 10–30 с після старту) вибраний вхід працює як звичайно.
- (P29) Список до 5 збережених мереж (SSID + пароль, порядок = пріоритет; NVS namespace `wifinets`, ключ `list`, один блоб із версією). Старт і втрата звʼязку: раунд = скан (якщо мереж ≥ 2) → видимі збережені за пріоритетом (інакше усі напряму) → спроби по черзі; після старту 3 невдалих раунди або бюджет 60 с → AP; під час роботи раунди повторюються без AP; підключений пристрій на мережу вищого пріоритету сам не перемикається. Портал AP додає мережу на ПЕРШЕ місце, решту не стирає (повний список → випадає остання). Стара одинична мережа з `esp_wifi` переноситься в список автоматично. Скидання Wi-Fi (API або утримання OK при старті) стирає ВСІ мережі й піднімає AP.
- Та сама веб-частина, що й для налаштувань: після підключення до мережі доступний повний інтерфейс за адресою mDNS (`audio.local`) і IP.

### Поточна поведінка (джерело правди — код; тут лише опорні факти)

- **Тракт.** Радіо: декодований потік ESP32-audioI2S → хук `audio_process_i2s` (EQ → вимір VU → `output_trim` (рівень станції) → `radio_volume`) → I2S0 → PCM5102 → підсилювач. Зовнішні входи: DPDT-реле → PCM1808 → `line_path` (I2S1 RX/TX slave) → PCM5102. DOUT GPIO18 мультиплексується між I2S0 (радіо) і I2S1 TX (прохід) через `esp_rom_gpio_connect_out_signal`.
- **Входи.** `defaults::kInputCount` = 3: 0 = радіо, 1 = TV Box (реле вимкнено), 2 = Computer (реле увімкнено); `audio/input_selector` (`begin`, `select(logicalInput)`, `current`; лише 1 / 2; лог `[SEL]`); радіо реле не чіпає; стан реле при старті = TV Box. Маска входів — 3 біти, дефолт 0x07 (радіо завжди 1). Назви за замовчуванням «WiFi Radio» / «TV Box» / «Computer» (редагуються у вебі).
- **`line_path` (`audio/line_path.{h,cpp}`).** Ресурси (канали I2S1, задача на ядрі 1, пріоритет 6, буфер 128 кадрів, ≈ 21,4–22,5 КБ внутрішньої RAM) існують лише між `start()` і `returnToRadio()`; під час проходу I2S0 фіксований на 48 кГц (`AudioPlayer::setFixedOutputRate`). API: `begin`, `start` (блокує до `kCreateWaitMs` = 500 мс), `requestStart` / `stop` / `returnToRadio` (неблокуючі), `isRunning`, `isStable`, `resourcesUp`, `state`, `lastError`, `setVolumeDb`, `setUserMute` (типово TRUE), `setBalanceDb` / `balanceDb`, `setEqBandDb` / `setEqAllDb` / `getEqAllDb` / `setEqBypass`, `stats`. Конвеєр float: RX int32 → float (`2^-31`; 24 біти left-aligned) → піки входу → `eq::Processor::processFloat` → VU (`VuSourceLinePath`, після EQ, до гучності, `kVuOffsetDb` = 20) → `DspVolume::processFloat` (гучність + баланс) → ОДНЕ насичення → піки виходу → TX; `LinePathStats::clipCount` = лише фінальне насичення. XSMT (GPIO45): LOW у задачі при старті / стопі / поверненні / Stall, HIGH при Starting → Running; мʼют користувача XSMT не чіпає (лише цифровий). Аварія: немає RX-блоків ≥ `kStallMs` = 300 мс → мʼют → Stalled → самовідновлення. Виміряно: старт ≈ 650 мс, `maxProcess` ≈ 440–500 мкс (бюджет ≈ 670 мкс), `lp.cycle 20` без витоку, вільна RAM після проходу ≈ 75 КБ (largest ≈ 33 КБ).
- **Автомат `AppController` (`LineState {Off, Starting, Active, Switching, Releasing, Failed}`).** Радіо → зовнішній: мʼют радіо, stop, чекати Idle, `input_selector::select`, гучність + EQ + баланс входу, `requestStart()`, Running → розмʼют; зовнішній ↔ зовнішній: без перезапуску проходу (мʼют → `kExtMuteSettleMs` = 40 мс → `select` → `kRelaySettleMs` = 30 мс → розмʼют); зовнішній → радіо: мʼют 40 мс, `returnToRadio()`, чекати `resourcesUp() == false`, потім потік; standby / restart / OTA: `lineRelease()`; помилки старту: один автоповтор через 1 с, далі `Failed` (тиша до явного вибору входу).
- **DSP.** `eq::Processor` — клас-екземпляр (радіо `g_radio` за фасадом `namespace eq` і власний у `line_path`, fs 48 кГц): 5 смуг peaking RBJ (DF2T, float, Q = 1,0), `designPeaking` (double) лише в сеттерах, `process()` / `processFloat()` без `double` і мʼютекса (seqlock), інтерполяція коефіцієнтів 20 мс. `DspVolume`: гучність і мʼют з посемпловим ramp (100 мс вгору / 20 мс мʼют), баланс — окремий прохід ПІСЛЯ гучності лише коли не нейтральний або іде перехід (ramp `balance_cfg::kRampMs` = 30 мс; при 0 бітово = без балансу); `radio_volume` — екземпляр радіо (старт замʼючений, викликається з хука останнім). Баланс: ±20 дБ, крок 1 дБ, додатній = вправо (лівий послаблюється), лише послаблення; `balance_cfg::kSwapChannels` = false (порядок L/R не перевірявся).
- **Гучність радіо.** `audio_cfg::radioVolumeDb(ui) = kRadioMaxVolumeDb (0) − volumeAttSteps(ui) × 1,25 дБ` (0 → −78,75; 50 → −20; 100 → 0 дБ; сумарно + рівень станції, типово −20 дБ); `AppController` без програмної рампи (`Phase` = {None, Settle}); цифровий мʼют перед XSMT / stop (`kRadioMuteWaitMs` = 60).
- **Налаштування (NVS v8, без міграцій; прошивка на СТЕРТИЙ flash).** `InputProfile{ volume, int8_t eqGainsDb[5], int8_t balanceDb, int8_t vuSensDb }` (8 Б) × 3 входи, імена `[3][32]`, маска; `Settings` 128 Б, blob 132 Б; приймається лише version == 8 і точний розмір, інакше дефолти. Профіль входу застосовується ПІД мʼютом при зміні входу, виході зі standby й на старті; мʼют користувача глобальний; усі зміни звуку проходять через одне місце в `AppController` (`persist()`; баланс і EQ екрана пишуться через `SettingsStore::modify`).
- **Екран «EQ + Balance» (`ui/screens.cpp`, `drawEqBalance()`).** Шапка «EQ + Balance» і назва входу (`fitText`), 6 вертикальних стовпчиків від нульової лінії (EQ ±12 і Bal ±20 — однакова піввисота, Bal іншого кольору), значення зі знаком, підписи `60` / `250` / `1k` / `4k` / `12k` / `Bal`, підсвітка вибраної колонки; вікно гучності на цьому екрані не малюється. Розкладка — `config/eq_screen_config.h` (`eq_screen_cfg`, колонки x = 10, 60, 110, 160, 210, 272). Дані: `AppStateData::eqSelected` (0..5), `eqGainsDb[5]`, `balanceDb` (публікуються лише при відкритому екрані, повторно кожні 200 мс).
- **«Тихий» перезапуск.** `AppController::prepareForRestart()` (static bool; блокує лише викликаючу задачу до `kPrepareRestartWaitMs` = 4000): мʼют → підсилювач LOW → пауза `kRestartMuteMs` = 300; сам `ESP.restart()` викликає викликач (`api_restart`, `ota_restart`, задача Wi-Fi), під час очікування веб-команди дають 503 `busy`. - **Діагностика `line_path`.** `config/line_path_diag_config.h`: `LINE_PATH_DIAG` = 0 (реліз); при 0 увесь діагностичний код компілюється геть. ### Стан плану й наступна фаза

План перебудови тракту й додаткових функцій ЗАВЕРШЕНО (усі кроки вище виконані). Нижче — те, що власник планує далі (рішення 2026-10-24).

**Наступна фаза (рішення власника): проєкт переробляється під ІНШЕ залізо — НОВИЙ ДИСПЛЕЙ і ПІДКЛЮЧЕНИЙ ПЛЕЄР на ESP32-WROOM-32 (media-модуль).**

*Що вже відомо про media-модуль (окрема прошивка, репозиторій `github.com/sjorchik/media_esp32`; факти — зі слів власника й документів того репозиторію: `README.md`, `HANDOFF.md`, `docs/UART_CONTRACT.md`):*
- ESP32-WROOM-32 (без PSRAM), PlatformIO. BT A2DP sink з метаданими AVRCP; MP3 з microSD (SPI) і з USB-флешки через CH376S (UART; модуль CH376S ще не прибув — етап M4a–c чекає заліза); вихід I2S → PCM5102 (власний ЦАП модуля).
- Звʼязок із S3 — UART1 за ФІКСОВАНИМ контрактом (`proto_ver` 2, кадри `$BODY*XX`), зокрема `HELLO,<ver>`, `SHUF`, `REP`, `EQ,<g1..g5>` (−12…+12 дБ), `LVL,<bt|sd|usb>,<−40..0>`; `EQ` і `LVL` зберігаються лише в RAM модуля, S3 має надсилати збережені значення після `HELLO,2` (як `SHUF` / `REP`). Власні цифровий 5-смуговий EQ (60 / 250 / 1k / 4k / 12k) і рівні по джерелах (sd / bt / usb) модуля НЕЗАЛЕЖНІ від EQ радіо на S3.
- Піни WROOM: I2S BCK 26, WS 25, DOUT 22, XSMT 27; SD (VSPI) SCK 18, MISO 19, MOSI 23, CS 5; CH376S (UART2) RX 16, TX 17; звʼязок із S3 (UART1) RX 32, TX 33; UART0 — лог і відлагоджувальна консоль. Таблицю розділів WROOM не чіпати (app 0x10000 / 0x3D0000, nvs 0x3E0000, без OTA).
- На стороні S3 резерв: UART1 (TX 42, RX 48) — розділ 3. КОД S3 для розмови з media-модулем (UART-лінк, екрани, веб) ЩЕ НЕ НАПИСАНО.

*Що НЕ відомо й треба з'ясувати першим у новому планувальному чаті (не вигадувати):*
1. Новий дисплей: модель / контролер, роздільність і орієнтація, інтерфейс (SPI / паралельний / RGB / I2C), піни, тачскрін, підсвітка, бібліотека; чи лишається ST7789 170×320.

3. Як звук media-модуля потрапляє на підсилювач: (а) аналоговий вихід його PCM5102 → реле / PCM1808 → `line_path` як ТРЕТІЙ зовнішній вхід; (б) окремий вихід / окреме комутування; (в) інакше. Від цього залежить кількість входів (`kInputCount`), реле й профілі (EQ, баланс, чутливість VU) для медіа.
4. Керування медіа з пристрою (екран, кнопки / енкодер / IR): джерело (BT / SD / USB), трек вперед / назад, пауза, shuffle / repeat, показ метаданих (виконавець / трек / час); чи потрібна сторінка веб-інтерфейсу; взаємодія EQ / рівня S3 і media-модуля (які значення S3 зберігає й шле після `HELLO,2`).

### Архітектурні рішення й інваріанти (дотримуватись у нових промптах)

1. Веб-команди керування виконує `AppController::runWebCommand()` (абсолютні значення, результат із `reason`), НЕ `EventBus`; з HTTP-хендлерів не чіпати залізо напряму (виняток — read-only геттери). Хендлери виконуються в задачі AsyncTCP: не блокувати; довгі й мережеві дії — через прапорці / задачі (шаблон «прапорець + задача wifi», відкладений `api_restart`).
2. Веб-сторінки ВБУДОВАНІ в прошивку як gzip-масиви (`webui/` → `tools/build_web.py` через `extra_scripts = pre:` → `src/net/web_assets_gen.cpp`, у `.gitignore`); LittleFS зберігає лише `stations.json` (не використовувати `uploadfs` — стирає станції). Нові сторінки додаються ЛИШЕ в `webui/` без правок C++. Конвенції фронтенду — `docs/web_ui.md`; усе від пристрою вставляти тільки через `textContent`.
3. Індекс станції ПОЗИЦІЙНИЙ (стабільного id немає); `AppController` не відстежує, яка станція реально грає після `move` / `remove`; сторінки перечитують список після кожної зміни.
4. Налаштування ПО ВХОДАХ: профіль входу = {гучність, пресет EQ на 5 смуг, баланс}; бас / дискант / gain / loudness ВИДАЛЕНО; усі зміни звуку — через одне місце в `AppController` (`persist()`).
5. Рівень станції: `Station::levelDb` (−24…0 дБ, за замовчуванням −20, `config/station_level_config.h`); послаблення — множення семплів у хуку `audio_process_i2s` (`audio/output_trim.*`), ДО початку звуку при запуску станції й наживо при редагуванні поточної; VU радіо рахується ПІСЛЯ EQ, але ДО `output_trim` (порядок у хуку: `eq::process` → VU → `output_trim::process` → `radio_volume` → I2S); `audio/vu_pcm_hook.cpp` НЕ підключає `Audio.h`; `VU_PCM_HOOK_STYLE != 1` → `#error` (вимикає VU й рівні станцій).
6. Підсилювач STBY: `pins::kAmpStby` = GPIO46 (1 = працює, 0 = standby; strapping-пін, внутрішній pull-down при скиданні); вмикання — пін HIGH під мʼютом, прогрів `kAmpWakeMs`, потім розмʼют; вимкнення — мʼют, через `kAmpOffDelayMs` LOW; `FEATURE_AMP_STANDBY`.
7. Розкладка flash: `otadata` обовʼязково на 0xE000 (`nvs` 0x9000 + 0x5000); `app0` / `app1` / `spiffs` не переміщувати; імʼя розділу LittleFS лишається `spiffs`. Процедури — `docs/flashing.md`.
8. IR: `kActionCount` = `GAIN_DOWN + 1` НЕЗМІННИЙ; 6 дій `BASS_UP/DOWN`, `TREBLE_UP/DOWN`, `GAIN_UP/DOWN` ЗАРЕЗЕРВОВАНІ в enum (не перенумеровувати; порядок безперервний, `static_assert`; `BALANCE_UP/DOWN` між ними ПРАЦЮЮТЬ), `AppController` зарезервовані ігнорує, з навчання виключено (`learnable = false`; `INPUT_AUX` теж); OK і BACK навчаються, `ENC_*` ні; формат NVS мапи не змінювався.
9. Режими мережі: поки піднята AP — `Mode::WifiSetup` на будь-якому вході (звук замʼючено, реагують лише POWER і коротке OK / клік енкодера); OK = офлайн (Wi-Fi вимкнено, усі входи крім радіо; не зберігається, вихід — перезапуск); утримання POWER ≥ `input_cfg::kPowerRestartHoldMs` (3 с) = «тихий» перезапуск у всіх режимах. Список мереж Wi-Fi — NVS `wifinets` (до 5, порядок = пріоритет, паролі не повертаються API); на мережу вищого пріоритету сам не перемикається; портал AP додає мережу першою.
10. Мова: написи на ДИСПЛЕЇ — англійською; веб-інтерфейс і документація — українською.
11. Еквалайзер: 5 смуг (`eq_cfg::kBandFreqHz`), peaking RBJ biquad; пресет ОКРЕМИЙ для кожного входу (у профілі): на екземпляр радіо застосовується пресет входу 0, на екземпляр `line_path` — пресет активного зовнішнього входу (`AppController::applyLineEq`); `/api/eq` приймає `input` (0…2), без `input` — поточний вхід.

## 14. Веб-API (огляд; повний контракт — `docs/web_api.md`)

Джерело правди — `docs/web_api.md` (прикріплювати до кожного веб-промпту; актуальний після P50a). Цей розділ — лише огляд.

| Група | Ендпоїнти |
|---|---|
| Стан | `GET /api/status` (+ `balance` = дБ активного входу, `vuSens` = чутливість VU активного входу, `menuContext` = `None` / `StationList` / `EqBalance`; без `processor` / тембру / `gain`), `GET` / `POST /api/settings` (назви входів, яскравість, `displayFlipped`; старі ключі тембру й `processorType` → 400 `unknown_field`) |
| Входи | `GET /api/inputs` → `{"inputs":[{index,name,available,enabled,selectable,canDisable}×3],"enabledMask":N,"input":N}`; `POST /api/inputs` `{"enabled":[…×3]}` або `{"index":N,"enabled":bool}`; 400 `no_body` / `invalid_json` / `unknown_field` / `missing_field` / `conflicting_fields` / `invalid_value` / `out_of_range`, 409 `ota_in_progress` / `ir_learn_active`, 413, 503 `busy`; вхід 0 завжди enabled |
| Керування | `POST /api/power` · `/api/mute` · `/api/volume` (value \| step) · `/api/input` (409 `input_disabled`) · `GET` / `POST /api/balance[?input=N]` · `/api/player/{play,pause,stop,toggle,next,prev}` · `/api/player/station`; `/api/gain` видалено (404) |
| Станції | `/api/stations*`: список, add / update / remove / move, імпорт JSON / M3U / PLS, експорт; поле `levelDb` (−24..0, за замовчуванням −20) |
| Чутливість VU | `GET /api/vu` (3 входи, межі −20 / 20, крок 1; `input` = активний); `POST /api/vu {"value":V[,"input":N]}` (активний → `runWebCommand`, неактивний → лише `Settings`) |
| Еквалайзер | `GET ?input=N` / `POST /api/eq`: 5 смуг, `gainsDb[5]` або `band` + `gainDb`, −12..+12 дБ; без `input` — поточний вхід (0…2) |
| IR | `/api/ir*`: навчання, мапа, імпорт / експорт |
| Wi-Fi | `GET /api/wifi`, `GET` / `POST /api/wifi/scan`, `POST /api/wifi/networks`, `POST /api/wifi/networks/move`, `DELETE /api/wifi/networks/{index}`, `POST /api/wifi/connect`, `POST /api/wifi/reset` (`confirm:true`, стирає ВСІ мережі) |
| Система | `GET /api/system`, `POST /api/system/reboot`, `POST /api/system/factory-reset` (`confirm:true`), `/api/ota` |

**Угоди:**
- Усі команди керування виконує `AppController::runWebCommand()`; з HTTP-хендлерів не чіпати залізо напряму (виняток — read-only геттери та програмний DSP: `/api/eq`, неактивний вхід у `/api/balance` — лише запис у `Settings`).
- Помилки — єдиний JSON-формат; для відмов керування є поле `reason`.
- Індекс станції позиційний, стабільного id немає; `station.name` у `GET /api/status` — назва зі списку (запасно ICY-назва).
- Хендлери виконуються в задачі AsyncTCP: не блокувати; reboot / factory-reset / wifi-reset відкладені одноразовою задачею `api_restart` із «тихою» підготовкою (`AppController::prepareForRestart()`), відповідь клієнту йде ДО перезапуску.
- Тіло JSON ≤ 1024 Б. `WEB_API_DEV_CORS` (за замовчуванням 0) — CORS для розробки сторінок на ПК.
- Статичні сторінки віддаються явними GET-маршрутами (`registerStaticRoutes`) з масивів у flash; `onNotFound` не змінювався (його використовує captive portal).
- IR-навчання: `POST /api/ir/learn` → `GET /api/ir/learn/status` (`Waiting`, `Confirm`, `Conflict`, `Success`, `Timeout`, `Idle`), далі `confirm-overwrite` / `cancel`.
- `waitForDevice` (фронтенд) опитує `GET /api/status` після перезапуску.
- Wi-Fi: індекси мереж позиційні; паролі API ніколи не повертає; мутуючі маршрути й скан відповідають 409 `ota_in_progress` / `ir_learn_active`, 503 `busy` під час перезапуску; `connect` відповідає ДО перемикання.
