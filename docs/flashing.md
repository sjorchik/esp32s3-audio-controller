# Прошивка пристрою: USB, OTA і розкладка flash

Стосується ESP32-S3 N16R8 (16 МБ flash), PlatformIO + pioarduino 55.03.37. Розкладка розділів — `partitions.csv` (з P24b).

## 1. Розкладка flash

| Область | Тип / підтип | Адреса | Розмір | Призначення |
|---|---|---|---|---|
| bootloader | — | 0x0000 | до 0x8000 | другий завантажувач (пише PlatformIO) |
| таблиця розділів | — | 0x8000 | 0x1000 | `partitions.bin` зі `partitions.csv` |
| `nvs` | data / nvs | 0x9000 | 0x5000 (20 КБ) | налаштування (формат v8), профілі входів, мапа пульта, Wi-Fi (див. розділ 8) |
| `otadata` | data / ota | 0xE000 | 0x2000 (8 КБ) | який слот (app0 / app1) завантажувати |
| (вільно) | — | 0x10000–0x1FFFF | 64 КБ | не використовується |
| `app0` | app / ota_0 | 0x20000 | 0x580000 (5,5 МБ) | прошивка, слот 0 |
| `app1` | app / ota_1 | 0x5A0000 | 0x580000 (5,5 МБ) | прошивка, слот 1 |
| `spiffs` | data / littlefs | 0xB20000 | 0x4E0000 (4,9 МБ) | LittleFS: `stations.json` |

Мітка `spiffs` навмисна: `LittleFS.begin()` в Arduino-ESP32 за замовчуванням шукає розділ із такою міткою. Попередження `gen_esp32part.py` про імʼя `spiffs` і підтип 0x83 під час збірки безпечне.

`otadata` стоїть саме на 0xE000, бо PlatformIO при USB-прошивці завжди пише `boot_app0.bin` (8 КБ) за адресою 0xE000, незалежно від таблиці. Не переміщуйте `otadata` і не збільшуйте `nvs` понад 0x5000, не звіривши адресу `boot_app0` у виводі `pio run -t upload -v`.

## 2. Прошивка по USB

```powershell
pio run -t upload
```

PlatformIO пише чотири образи: `bootloader.bin` → 0x0000, `partitions.bin` → 0x8000, `boot_app0.bin` → 0xE000, `firmware.bin` → 0x20000 (app0). Наслідки:

- `boot_app0.bin` повністю перезаписує `otadata`, тож після USB-прошивки пристрій завжди стартує зі слота **app0**, навіть якщо до цього працював app1 після OTA.
- `nvs` (налаштування) і `spiffs` (станції) USB-прошивка не чіпає. Виняток — зміна формату налаштувань (NVS v8): тоді прошивають на стертий flash, див. розділ 8.
- Адреси й образи можна подивитись так: `pio run -t upload -v 2>&1 | Select-String "write_flash|write-flash|boot_app0"`.

Не використовуйте `pio run -t uploadfs`: він перезаписує весь розділ LittleFS і стирає станції. Веб-сторінки вбудовані в прошивку, окремо їх заливати не потрібно.

## 3. Оновлення через OTA

Сторінка «Система» → «Оновлення прошивки». Образ пишеться в **неактивний** слот, після перевірки оновлюється `otadata`, пристрій перезапускається й стартує з нового слота. Слоти чергуються: app0 → app1 → app0 → …

Після OTA пристрій працює зі слота app1 (лог `[MAIN] Running partition: app1`). Наступна USB-прошивка повертає його на app0 (див. розділ 2).

## 4. Пристрій стартує не з того слота

1. Подивіться рядок `[MAIN] Running partition: …` у логу при старті.
2. Якщо після USB-прошивки там `app1`, скиньте вибір слота (стирається лише `otadata`, налаштування й станції не чіпаються):

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\esptool.exe" --chip esp32s3 --port COM4 erase-region 0xE000 0x2000
```

Порт `COM4` замініть на свій. Без дійсного `otadata` завантажувач запускає `app0`. У старіших версіях esptool команда називається `erase_region`.

Якщо це відбувається на новій розкладці після звичайної USB-прошивки, перевірте, що в `partitions.csv` `otadata` справді на 0xE000, а в логу `pio run -t upload -v` `boot_app0.bin` пишеться за 0xe000.

## 5. Міграція зі старої розкладки (nvs 0x9000 + 0x6000, otadata 0xF000)

Станції в LittleFS (0xB20000 і далі) міграція не чіпає. Налаштування (NVS) втрачаються.

1. **Експорт.** На сторінці `/stations` натисніть «Експорт», на сторінці `/ir` — «Експорт» (мапа пульта). Назви входів, профілі входів (гучність, EQ, баланс, чутливість VU) і Wi-Fi експорту не мають: їх доведеться ввести вручну.
2. **Стерти ділянку старих `nvs` + `otadata`** (0x9000…0x10FFF: старий `nvs` 0x9000–0xEFFF разом зі старим `otadata` 0xF000–0x10FFF; `app0` з 0x20000 не зачіпається):

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\esptool.exe" --chip esp32s3 --port COM4 erase-region 0x9000 0x8000
```

3. **Повна USB-прошивка** (bootloader, нова таблиця, `boot_app0`, прошивка):

```powershell
pio run -t upload
```

   У логу має бути `[MAIN] Running partition: app0`.
4. **Після першого запуску:** NVS порожній, тож налаштування за замовчуванням; Wi-Fi треба налаштувати заново через AP-портал `AudioCtrl-Setup`; станції на місці; імпортуйте мапу пульта, за потреби задайте назви входів і звук.

## 6. Відновлення

- Скинути вибір слота: розділ 4.
- Скинути лише налаштування (NVS), не чіпаючи станції:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\esptool.exe" --chip esp32s3 --port COM4 erase-region 0x9000 0x5000
```

- **Повне стирання flash** (`erase-flash` або `pio run -t erase`, див. також розділ 8) — лише за потреби: при зміні формату налаштувань або в крайньому разі. Воно стирає ВСЕ, зокрема станції (LittleFS), налаштування й Wi-Fi. Перед ним експортуйте станції й мапу пульта.

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\esptool.exe" --chip esp32s3 --port COM4 erase-flash
```

  Після цього виконайте повну USB-прошивку (`pio run -t upload`). Розділ LittleFS без даних створиться при першому запуску, станції треба імпортувати.

## 7. Контрольний сценарій після міграції

1. Змінити налаштування (наприклад, назву входу) → прошити по USB ще раз → налаштування збереглись.
2. Оновити прошивку через OTA зі сторінки «Система» → стартує app1.
3. Прошити по USB → стартує app0 **без** ручного `erase-region`, налаштування збереглись.

## 8. Зміна формату налаштувань (NVS v8): прошивка на стертий flash

Поточний формат налаштувань у NVS — **v8**. Міграції зі старіших версій (зокрема v7) немає: прошивка приймає лише запис версії 8 точного розміру, інакше стартує з типовими значеннями. Тому при переході на цю версію (і взагалі при зміні формату налаштувань) пристрій прошивають на **стертий** flash.

### Що зберігається в NVS (і втрачається при стиранні)

| Namespace | Що там |
|---|---|
| `audioctl` | налаштування: назви входів, яскравість, орієнтація дисплея, маска ввімкнених входів, останні вхід і станція, профілі трьох входів (гучність, EQ 5 смуг, баланс, чутливість VU) |
| `wifinets` | список до 5 збережених Wi-Fi-мереж (SSID і паролі) |
| (NVS) | мапа навчених кодів ІЧ-пульта |

Станції лежать не в NVS, а в LittleFS (`spiffs`, `stations.json`).

### Процедура

1. **Експорт.** На сторінці `/stations` — «Експорт» (станції), на сторінці `/ir` — «Експорт» (мапа пульта). Налаштування, профілі входів і Wi-Fi експорту не мають: їх доведеться ввести заново.
2. **Повне стирання flash:**

```powershell
pio run -t erase
```

3. **Повна USB-прошивка** (bootloader, таблиця розділів, `boot_app0`, прошивка):

```powershell
pio run -t upload
```

   У логу має бути `[MAIN] Running partition: app0`.
4. **Після першого запуску:** усе за замовчуванням (пристрій у standby — натисніть POWER); Wi-Fi налаштувати через AP-портал `AudioCtrl-Setup`; імпортувати станції (`/stations`) і мапу пульта (`/ir`); за потреби задати назви входів, гучність, EQ, баланс і чутливість VU.

### Що втрачається, а що ні

| Спосіб | Налаштування, Wi-Fi, мапа пульта (NVS) | Станції (LittleFS) |
|---|---|---|
| `pio run -t erase` (повне стирання flash) | втрачаються | втрачаються |
| `esptool erase-region 0x9000 0x5000` (лише `nvs`, розділ 6) | втрачаються | **лишаються** |
| `pio run -t upload` без стирання | лишаються, але при іншій версії формату ігноруються (беруться типові значення) | лишаються |

> **Потребує підтвердження:** що `pio run -t erase` на цій збірці стирає flash повністю так само, як `esptool erase-flash` (розділ 6), зокрема LittleFS зі станціями. Поки не підтверджено на пристрої, вважайте, що станції теж втрачаються, і експортуйте їх заздалегідь.

Якщо потрібно лише скинути налаштування й зберегти станції, див. розділ 6 («Скинути лише налаштування»).
