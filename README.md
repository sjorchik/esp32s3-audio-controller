# ESP32-S3 Audio Controller

Інтернет-радіо та аудіоконтролер на ESP32-S3: потокове радіо плюс два зовнішні аналогові входи (TV Box і Computer). Звук обробляється цифрово: зовнішні входи йдуть через АЦП PCM1808 в ESP32, радіо декодується програмно, а на виході — ЦАП PCM5102 і підсилювач. Для кожного входу окремо зберігаються гучність, 5-смуговий еквалайзер, баланс і чутливість VU-метра. Керування — енкодером, кнопками та ІЧ-пультом RC5, кольоровий дисплей ST7789 із VU-метром, веб-інтерфейс, оновлення прошивки по Wi-Fi (OTA). Збірка — VS Code + PlatformIO, Arduino framework.

Репозиторій: https://github.com/sjorchik/esp32s3-audio-controller

## Можливості

**Радіо**
- Потокове відтворення через ESP32-audioI2S, метадані (ICY), автоперепідключення.
- Список станцій у LittleFS (`stations.json`): додавання, редагування, переміщення, імпорт JSON / M3U / PLS, експорт.
- Рівень виходу декодера по станціях (`levelDb`, −24…0 дБ, за замовчуванням −20 дБ) — цифрове послаблення перед ЦАП.

**Входи**
- Три логічні входи: 0 — WiFi Radio, 1 — TV Box, 2 — Computer. Назви редагуються у вебі.
- Два зовнішні входи комутує одне DPDT-реле; сигнал іде в АЦП PCM1808, далі цифровим трактом у ESP32 і на ЦАП PCM5102.
- Входи 1 і 2 можна вимкнути (вимкнені пропускаються при перемиканні й ховаються на «Головній» та «Аудіо»); радіо вимкнути не можна.
- Профіль входу зберігається окремо для кожного з трьох входів: гучність, еквалайзер (5 смуг), баланс, чутливість VU. Мʼют — загальний.

**Звук**
- Цифрова гучність, 5-смуговий еквалайзер (±12 дБ) і баланс (±20 дБ) — окремі налаштування для кожного входу, застосовуються при перемиканні входу під мʼютом.
- Мʼякий мʼют (цифровий + XSMT ЦАПа) і керований вихід STBY підсилювача: клацань при перемиканні, standby й перезапуску бути не повинно.
- Аналогових аудіочіпів (TDA7318 / PT2313L) і тембру (бас / дискант), gain та loudness більше немає.

**Дисплей**
- ST7789 170×320 (горизонтально 320×170), україномовний растровий шрифт на основі DejaVu Sans (написи на дисплеї — англійською).
- Екран Radio: назва станції, рядок метаданих / статусу потоку, рядок `SSID  IP`, іконка Wi-Fi за рівнем сигналу, VU-метр.
- Екран зовнішнього входу: назва входу (колір залежить від входу), та сама верхня стрічка й VU.
- VU-метр показує середньоквадратичний (RMS) рівень сигналу для радіо й обох зовнішніх входів; чутливість налаштовується окремо для кожного входу. На зовнішніх входах VU знімається після еквалайзера й до регулятора гучності, тому не залежить від положення регулятора.
- Екран «EQ + Balance»: 6 вертикальних стовпчиків (5 смуг EQ і баланс) активного входу.
- Спливне вікно з великими цифрами при зміні гучності й балансу.

**Керування**
- Енкодер (апаратний PCNT) з кнопкою, 6 кнопок, ІЧ-пульт RC5 / RC5X, кнопки пульта навчаються користувачем.

**Веб**
- Сім сторінок (українською), без CDN і фреймворків, вбудовані в прошивку. Повний REST API.
- Іконка ярлика для головного екрана телефона.

**Wi-Fi**
- До 5 збережених мереж із пріоритетом, режим AP з captive portal для першого налаштування, офлайн-режим.

**Система**
- Standby (з холодного старту пристрій стартує у standby), «тихий» перезапуск, OTA через веб, factory reset, налаштування в NVS.

## Апаратна частина

| Компонент | Призначення |
|---|---|
| ESP32-S3 N16R8 | 16 МБ flash, 8 МБ octal PSRAM |
| PCM5102 | ЦАП (I2S); SCK заземлений (внутрішній PLL, MCLK не потрібен); вихід (≈ 2,1 Vrms при 0 dBFS) іде на підсилювач |
| PCM1808 | АЦП зовнішніх входів (I2S slave); MCLK, BCLK і LRCLK дає ESP32 |
| DPDT-реле | Вибір зовнішнього входу (TV Box / Computer), керується одним GPIO |
| Підсилювач | Окремий; вивід STBY керується прошивкою |
| ST7789 170×320 | Дисплей, SPI2 (FSPI), підсвітка — LEDC PWM |
| VS1838B | ІЧ-приймач (RMT RX), протокол RC5 / RC5X |
| Енкодер + 6 кнопок | POWER, UP, DOWN, LEFT, RIGHT, OK |

Живлення: одне джерело 12 В → 5 В, 3.3 В.

Аудіочіпів TDA7318 / PT2313L і шини I2C у проєкті немає. Bluetooth і AUX-входу немає (UART1 зарезервовано під майбутній Bluetooth-модуль).

### Мапа пінів

Єдине джерело — `src/config/pins.h`. Заборонені піни ESP32-S3: GPIO 26–37 (flash / PSRAM), 19 / 20 (USB).

| Блок | Сигнал | GPIO |
|---|---|---:|
| ST7789 | SCLK / MOSI / CS | 12 / 11 / 10 |
| | DC / RST / BLK | 9 / 13 / 14 |
| I2S | BCLK | 15 |
| | WS (LRCLK) | 17 |
| | DOUT → DIN PCM5102 | 18 |
| | MCLK (для PCM1808) | 16 |
| | DIN ← PCM1808 | 8 |
| PCM5102 | XSMT (active-low, pulldown 10 кОм) | 45 |
| Реле входів | DPDT (HIGH = Computer, вимкнено = TV Box) | 1 |
| Підсилювач | STBY (1 = працює, 0 = standby) | 46 |
| Енкодер | A / B / кнопка | 4 / 5 / 6 |
| Кнопки | POWER | 7 |
| | UP / DOWN | 21 / 38 |
| | LEFT / RIGHT / OK | 39 / 40 / 41 |
| IR | VS1838B OUT | 47 |
| Резерв BT | UART1 TX / RX | 42 / 48 |
| Консоль | UART0 TX / RX | 43 / 44 |

### Примітки до схеми

- **BCLK (GPIO15) і LRCLK (GPIO17) спільні** для PCM5102 і PCM1808. MCLK (GPIO16) виводить для АЦП ESP32.
- **PCM1808** у slave-режимі: стрепи MD0 = MD1 = FMT = GND (I2S 24 біти, MCLK/fs автоматично).
- **Вхід АЦП** береться безпосередньо від DPDT-реле входів. Земля джерел, реле й модуля PCM1808 має бути спільною.
- **УВАГА: вхідне коло модуля PCM1808.** На деяких модулях на вході стоїть RC-фільтр. Фільтр «10 кОм + кераміка 220 нФ» (зріз ≈ 72 Гц) треба прибрати: з ним звук зовнішніх входів «в діжці», без високих частот. При заміні модуля перевірте номінали: частота зрізу має бути значно вищою за 20 кГц.
- **Реле входів** (GPIO1): рекомендовано pulldown на затворі / базі драйвера реле, щоб при старті було вибрано TV Box.
- **XSMT** краще тримати під керуванням прошивки: постійне підключення до +3.3 В прибирає захист від клацань при завантаженні, зміні станції, standby й OTA.
- **GPIO46 (STBY)** — strapping-пін: при скиданні підсилювач у standby; рекомендовано зовнішній резистор 10 кОм до GND.

## Швидкий старт

### Вимоги

- VS Code з розширенням PlatformIO (або PlatformIO Core).
- Python 3 (скрипт `tools/build_web.py` використовує лише стандартну бібліотеку; запускається автоматично перед кожною збіркою).
- USB-підключення до плати. Консоль — UART0 (USB CDC вимкнено), швидкість 115200.

Платформа — pioarduino 55.03.37 (Arduino-ESP32 3.3.7 / IDF 5.5.2), плата `esp32-s3-devkitc-1`, `qio_opi`. Середовище PlatformIO одне — `esp32s3`.

### Збірка й прошивка

```bash
git clone https://github.com/sjorchik/esp32s3-audio-controller.git
cd esp32s3-audio-controller

pio run -e esp32s3                 # збірка
pio run -e esp32s3 -t upload       # прошивка по USB
pio device monitor                 # Serial-монітор (115200)
```

Веб-сторінки окремо заливати не потрібно: `webui/` стискається gzip і вбудовується в прошивку (`tools/build_web.py` → `src/net/web_assets_gen.cpp`, файл у `.gitignore`). Після зміни `webui/` достатньо перепрошити пристрій. Вручну: `python tools/build_web.py`.

> Не використовуйте `pio run -t uploadfs`: він стирає розділ LittleFS разом зі списком станцій. Сторінки там не зберігаються.

#### Прошивка на стертий flash (формат налаштувань NVS v8)

Поточний формат налаштувань у NVS — **v8**, без міграції зі старіших версій. Тож при першій прошивці цієї версії (і взагалі при зміні формату налаштувань) пристрій прошивають на **стертий** flash:

```bash
pio run -e esp32s3 -t erase        # повне стирання flash
pio run -e esp32s3 -t upload       # повна USB-прошивка
```

Стирання знищує все, що було у flash: налаштування (назви входів, профілі входів — гучність, EQ, баланс, чутливість VU, яскравість, орієнтація), список Wi-Fi-мереж, навчені коди ІЧ-пульта й станції в LittleFS. Станції та мапу пульта перед стиранням експортуйте на сторінках `/stations` і `/ir`. Деталі — у [`docs/flashing.md`](docs/flashing.md).

Таблиця розділів (`partitions.csv`, 16 МБ): `nvs`, `otadata`, два OTA-слоти `app0` / `app1` по 0x580000 і LittleFS (розділ з міткою `spiffs`). `otadata` має лишатися на 0xE000, бо збірка пише туди `boot_app0.bin`. Процедури прошивки, міграції й відновлення — [`docs/flashing.md`](docs/flashing.md).

### Перший запуск

1. Після подачі живлення пристрій стартує у **standby** — натисніть **POWER**.
2. Якщо збереженої Wi-Fi-мережі немає (або три спроби підключення невдалі), пристрій піднімає точку доступу **`AudioCtrl-Setup`** і captive portal. Підключіться до неї, відкрийте сторінку порталу (адреса `192.168.4.1`), оберіть мережу зі скану, введіть пароль. Дані зберігаються в NVS, пристрій перезапускається в режимі STA.
3. Поки піднята AP, пристрій у режимі «Setup Wi-Fi»; **OK** вмикає офлайн-режим (Wi-Fi вимкнено, доступні всі входи, крім радіо).
4. Після підключення веб-інтерфейс доступний за `http://audio.local/` або за IP (його показано на дисплеї).
5. Скинути всі збережені мережі: утримувати **OK** під час старту, або «Система → Скинути Wi-Fi» у вебі.

> Після холодного старту (подача живлення, brownout) пристрій у standby, тому налаштування Wi-Fi через AP потребує натискання POWER.

## Керування

### Енкодер

| Дія | Результат |
|---|---|
| Обертання | Гучність |
| Клік | Мʼют (перемикання) |
| Утримання | Екран «EQ + Balance» (на списку станцій — мʼют) |

При зміні гучності чи балансу на дисплеї 5 с показується спливне вікно з великими цифрами; воно гасне раніше від натискання будь-якої кнопки.

### Екран «EQ + Balance»

Показує 6 стовпчиків активного входу: п'ять смуг еквалайзера (60 Гц, 250 Гц, 1 кГц, 4 кГц, 12 кГц; ±12 дБ) і баланс (±20 дБ). Зміни застосовуються одразу й зберігаються в профілі входу.

| Дія | Результат |
|---|---|
| Клік енкодера або RIGHT | Наступний параметр (60 → 250 → 1k → 4k → 12k → Bal → 60) |
| LEFT | Попередній параметр |
| UP / DOWN або обертання енкодера | Вибраний параметр ±1 дБ |
| Утримання енкодера, BACK (пульт) або 10 с без дій | Вихід |

Екран закривається сам при standby, OTA, початку навчання пульта, зміні входу, підніманні AP і веб-командах станцій.

### Кнопки

| Кнопка | Головний екран |
|---|---|
| UP / DOWN | Перемикання входу (вимкнені входи пропускаються) |
| LEFT / RIGHT | Перемикання станції (лише вхід Radio) |
| OK, коротко | Play / pause (лише Radio) |
| OK, утримання | Список станцій (лише Radio) |
| POWER | Standby вкл / викл |
| POWER, утримання ≥ 3 с | «Тихий» перезапуск (мʼют → STBY підсилювача → перезапуск) |
| OK під час старту | Скидання збережених мереж Wi-Fi |

Список станцій: обертання енкодера, UP / DOWN — вибір; OK або клік енкодера — запустити станцію; BACK (пульт) — вихід.

Режим «Setup Wi-Fi» (AP): реагують лише POWER і коротке OK / клік енкодера.

### ІЧ-пульт

Протокол RC5 / RC5X. Кнопки пульта навчаються на сторінці «Пульт» у вебі: гучність, мʼют, прямий вибір входу (Radio / TV Box / Computer), баланс ±1 дБ, навігація (зокрема OK і BACK) та інші дії зі списку на сторінці. Дії енкодера (`ENC_*`) не навчаються. Коди зберігаються в NVS; мапу можна експортувати й імпортувати як JSON.

## Веб-інтерфейс

Адреса: `http://audio.local/` або IP пристрою, порт 80. HTTPS і автентифікації немає.

| Сторінка | Шлях | Що можна робити |
|---|---|---|
| Головна | `/` | Плеєр (now playing, кнопки), вибір входу, гучність і мʼют, станції, standby; вимкнені входи не показуються; помітно, коли на пристрої відкрите меню |
| Станції | `/stations` | Список із пошуком, додавання, редагування, переміщення, рівень станції, імпорт / експорт |
| Аудіо | `/audio` | Для кожного з трьох входів (вкладки): еквалайзер 5 смуг і баланс, скидання параметра або всього входу. Вкладки лише вибирають профіль для редагування й не перемикають вхід на пристрої |
| Пульт | `/ir` | Навчання кнопок ІЧ-пульта, очищення, імпорт / експорт мапи |
| Налаштування | `/settings` | Назви входів; блок «Входи»: галочка активації кожного входу і повзунок чутливості VU (−20…+20 дБ); яскравість і орієнтація дисплея |
| Wi-Fi | `/wifi` | Збережені мережі (пріоритет, видалення), скан, додавання, підключення |
| Система | `/system` | Інформація про пристрій, перезапуск, скидання, скидання Wi-Fi, оновлення прошивки (OTA) |

Для кожної `x.html` є псевдонім `/x`.

**Чутливість VU.** Це зсув показу індикатора рівня в дБ, окремий для кожного входу. На звук вона не впливає й на самому пристрої не регулюється — лише в «Налаштування → Входи».

**Ярлик на телефоні.** Сторінки містять PNG-іконки й `manifest.webmanifest`, тому ярлик «Додати на головний екран» отримує іконку (перевірено на Android: Opera / Chrome). Сторінка віддається по HTTP, тож це звичайний ярлик-закладка, а не встановлений PWA. Після заміни іконок старий ярлик на телефоні треба видалити й додати наново.

Документація:
- [`docs/web_ui.md`](docs/web_ui.md) — каркас фронтенду, як додати сторінку, компоненти CSS, функції `common.js`.
- [`docs/web_api.md`](docs/web_api.md) — повний контракт HTTP API.

Огляд API (усі шляхи починаються з `/api/`):

| Група | Ендпоїнти |
|---|---|
| Стан і налаштування | `status`, `settings` |
| Керування | `power`, `mute`, `volume`, `input`, `balance`, `player/{play,pause,stop,toggle,next,prev,station}` |
| Входи | `inputs` (вмикання / вимикання входів) |
| Станції | `stations*` (CRUD, move, import, export) |
| Еквалайзер | `eq` (по входах) |
| Чутливість VU | `vu` (по входах) |
| IR | `ir*` |
| Wi-Fi | `wifi*` |
| Система | `system`, `system/reboot`, `system/factory-reset`, `ota` |

Для швидкої перевірки API є `tools/web_api_smoke.py` (лише стандартна бібліотека):

```bash
python tools/web_api_smoke.py audio.local          # лише читання
python tools/web_api_smoke.py audio.local --write  # з POST-перевірками
```

## Конфігурація

Усі піни, таймінги, розміри буферів і прапорці — у `src/config/`. Значення дивіться в самих файлах.

| Файл | Що налаштовується |
|---|---|
| `pins.h` | Мапа пінів |
| `features.h` | `ENABLE_VU`, `ENABLE_WEB`, `ENABLE_MDNS`, `FEATURE_AMP_STANDBY`, `ENABLE_BT_UART` (резерв, 0) |
| `defaults.h` | Загальні константи (кількість входів, черга подій тощо) |
| `app_controller_config.h` | Пріоритети, пороги, таймінги переходів і перезапуску, холодний старт у standby |
| `line_path_config.h` | Прохід зовнішніх входів (PCM1808 → ESP32 → PCM5102): `LINE_PATH_ENABLE`, параметри I2S / DMA, таймаути |
| `line_path_diag_config.h` | Діагностика проходу (`LINE_PATH_DIAG`) |
| `input_selector_config.h` | Реле входів: активний рівень, пауза контактів |
| `audio_config.h`, `dsp_volume_config.h` | Шкала гучності радіо, рампи цифрової гучності |
| `balance_config.h` | Діапазон і крок балансу, порядок каналів |
| `eq_config.h`, `eq_screen_config.h` | Частоти смуг, діапазон ±12 дБ, Q; розкладка екрана «EQ + Balance» |
| `vu_config.h` | Шкала й балістика VU, режим виміру `VU_MEASURE_MODE` (1 = RMS, 0 = пік) |
| `vu_sens_config.h` | Діапазон і крок чутливості VU |
| `screens_config.h` | Розкладка екранів 320×170, кольори, спливне вікно |
| `display_config.h` | Параметри панелі, розміри шрифтів |
| `station_level_config.h`, `station_store_config.h` | Рівень станції; сховище станцій |
| `wifi_config.h`, `wifi_status_config.h` | Таймаути STA / AP, ліміт збережених мереж, рівень сигналу |
| `web_server_config.h`, `web_api_config.h`, `web_static_config.h` | Порт, ліміти тіла, `WEB_API_DEV_CORS`, версія прошивки в API |
| `input_config.h`, `ir_config.h`, `ir_learn_ui_config.h` | Кнопки, енкодер, IR |
| `audio_player_config.h`, `amp_config.h` | Плеєр; затримки STBY підсилювача |
| `settings_config.h` | Формат і версія налаштувань у NVS |

Типові зміни:
- **Холодний старт не в standby** — параметри холодного старту в `app_controller_config.h`.
- **Вимкнути VU** — `ENABLE_VU 0` у `features.h`.
- **VU за піком замість RMS** — `VU_MEASURE_MODE 0` у `vu_config.h`.
- **Помінялись місцями лівий і правий канали при балансі** — порядок каналів у `balance_config.h`.

### Де зберігаються дані

- **NVS** (namespace `audioctl`): назви входів, яскравість, орієнтація, профілі входів (гучність, EQ 5 смуг, баланс, чутливість VU), маска ввімкнених входів, останній вхід і станція. Формат — версійований blob (зараз v8); приймається лише поточна версія, міграцій зі старих немає: інакше налаштування беруться за замовчуванням.
- **NVS** (namespace `wifinets`): список до 5 мереж Wi-Fi.
- **NVS**: мапа ІЧ-пульта.
- **LittleFS**: `stations.json`.

## Архітектура

### Звуковий тракт

- **Радіо:** декодований потік (ESP32-audioI2S) → еквалайзер → вимір VU → рівень станції → цифрова гучність (і баланс) → I2S → PCM5102 → підсилювач.
- **Зовнішні входи:** DPDT-реле → PCM1808 → прохід `line_path` (I2S, 48 кГц): еквалайзер → вимір VU → гучність і баланс → PCM5102 → підсилювач. Перемикання на зовнішній вхід займає близько 0,65 с.

Еквалайзер, гучність і баланс — програмні (DSP в ESP32); пресет EQ і баланс беруться з профілю активного входу.

### Модулі `src/`

| Папка | Роль |
|---|---|
| `config/` | Усі константи й прапорці |
| `core/` | `events` (черга подій), `app_state`, `app_controller`, `settings` (NVS), `action_names` |
| `input/` | `buttons`, `encoder` (PCNT), `ir_rc5` (RMT, декодер, навчання) |
| `audio/` | `audio_player` (ESP32-audioI2S), `line_path` (прохід зовнішніх входів), `input_selector` (реле), `dsp_volume`, `radio_volume`, `output_trim`, `eq`, `vu_source`, `vu_math`, `vu_pcm_hook`, `amp_standby` |
| `stations/` | `station_store` (LittleFS JSON, імпорт M3U / PLS / JSON) |
| `ui/` | `display` (LovyanGFX), `fonts`, `icons`, `screens` |
| `net/` | `wifi_manager`, `wifi_networks`, `mdns`, `web_server`, `web_api_*`, `web_static` |
| `main.cpp` | Ініціалізація модулів |

### Потоки керування

Джерела (кнопки, енкодер, IR) → `EventBus` (одна FreeRTOS-черга) → `AppController` → модулі. Стан зберігається в `AppState` (потокобезпечний доступ). Веб-команди виконує `AppController::runWebCommand()`, не `EventBus`; з HTTP-хендлерів залізо не чіпається напряму.

### Ядра

- **Ядро 0:** введення, `AppController`, UI / дисплей, Wi-Fi, веб-сервер.
- **Ядро 1:** лише аудіо (ESP32-audioI2S, декодування, I2S, задача проходу зовнішніх входів). `loop()` порожній.

### Інваріанти (не ламати)

- Порядок у PCM-хуку радіо: `eq::process` → вимір VU → `output_trim::process` → гучність → I2S.
- `audio/vu_pcm_hook.cpp` не підключає `Audio.h`.
- Єдине джерело пінів — `config/pins.h`; піни не змінювати без потреби.
- Модулі не викликають один одного для керування — лише через події й `AppState`.
- I2S напряму не чіпати: ним володіє ESP32-audioI2S. Використовувати лише нові драйвери IDF 5.x (PCNT, RMT, LEDC через `ledcAttach`).
- Великі буфери й спрайти — у PSRAM.
- Написи на дисплеї — англійською; веб-інтерфейс і документація — українською. Логи Serial — англійською з тегом модуля (`[IR] ...`).
- Звук зберігається по входах; зміна звуку проходить через одне місце в `AppController`.

### Генератори шрифтів

Шрифт — DejaVu Sans (`tools/fonts/DejaVuSans.ttf`), потрібні Python 3 і Pillow. Результати вже є в репозиторії (`src/ui/font_*.h`); запускати генератори треба лише при зміні розмірів. Команди з кореня проєкту:

```bash
# Large / Small / Tiny (+ необовʼязково прев'ю)
python3 tools/gen_gfxfont.py --ttf tools/fonts/DejaVuSans.ttf --out src/ui/font_data.h --preview tools/font_preview.png

# XLarge — назва станції (yAdvance 36)
python3 tools/gen_xlarge_font.py --ttf tools/fonts/DejaVuSans.ttf --out src/ui/font_xlarge_data.h --em 30

# Digits — цифри спливного вікна
python3 tools/gen_digits_font.py --ttf tools/fonts/DejaVuSans.ttf --out src/ui/font_digits_data.h --em 112
```

Надрукований `yAdvance` має збігатися з відповідною константою в `display_config.h` (`kFontXLargePx`, `kFontDigitsPx`).

## Оновлення прошивки та скидання

**OTA.** Сторінка «Система → Оновлення прошивки» завантажує `.bin` (збірка `.pio/build/esp32s3/firmware.bin`) з індикацією прогресу. Те саме через API:

```bash
curl -X POST --data-binary @firmware.bin -H "Content-Type: application/octet-stream" http://audio.local/api/ota
```

Під час OTA звук зупиняється, екран показує прогрес; після успіху пристрій «тихо» перезапускається приблизно через 1.5 с. Оновлюється лише прошивка (веб-сторінки вбудовані в неї, окремого оновлення не потребують). Автоматичного відкату на попередню прошивку немає. Якщо нова прошивка змінює формат налаштувань NVS, потрібна прошивка по USB на стертий flash (див. вище й [`docs/flashing.md`](docs/flashing.md)).

**Скидання.**

| Дія | Що робить |
|---|---|
| Система → «Скинути налаштування» (`factory-reset`) | Налаштування (назви входів, маска входів, яскравість, орієнтація, профілі входів — гучність, EQ, баланс, чутливість VU, останній вхід / станція) — до заводських. Станції, мапа IR і мережі Wi-Fi не чіпаються |
| Система → «Скинути Wi-Fi» або утримання OK при старті | Стирає ВСІ збережені мережі, пристрій стартує в режимі AP |
| `pio run -t erase` | Повне стирання flash: налаштування, Wi-Fi, мапа IR і станції. Див. [`docs/flashing.md`](docs/flashing.md) |

## Відомі обмеження

- Веб-API без автентифікації й без HTTPS: reboot, factory-reset, OTA і список Wi-Fi доступні будь-кому в мережі. Використовуйте лише в довіреній локальній мережі.
- Паролі Wi-Fi зберігаються в NVS у відкритому вигляді; WPA2-Enterprise не підтримується.
- OTA без автовідкату.
- Індекс станції позиційний; стабільного id немає.
- Режим AP: основний API недоступний, відповідає лише портал налаштування.
- Офлайн-режим не зберігається, вихід з нього — перезапуск.
- Налаштування у NVS мають лише поточну версію формату (v8), міграцій немає.
- VU показує RMS: на динамічній музиці він помітно нижчий за піковий рівень; для підстроювання є чутливість VU. Цифрова тиша чутливістю не піднімається.
- Чутливість VU змінюється лише у вебі, на пристрої регулятора немає.
- Не перевірено на залізі: шум PCM5102 і підсилювача при малій цифровій гучності та при цифровому мʼюті; порядок каналів L / R (баланс); затримка проходу зовнішніх входів.
- Мобільну розкладку веб-інтерфейсу не перевірено на вузьких екранах і в iOS Safari; ярлик на головному екрані перевірено лише на Android.

### Діагностика

Логи йдуть в Serial (UART0, 115200) з тегами модулів, наприклад `[MAIN]`, `[IR]`. Додаткові повідомлення вмикаються прапорцями в `src/config/`: `INPUT_DEBUG`, `IR_DEBUG`, `APP_CONTROLLER_DEBUG`, `LINE_PATH_DEBUG`, `VU_DEBUG`, `AMP_DEBUG`, `EQ_DEBUG` та прапорці групи `STATION_STORE_*`.

Тестові й діагностичні режими: `LINE_PATH_TEST` (тестові команди проходу зовнішніх входів), `LINE_PATH_DIAG` (консольні `lp.*`; працюють лише разом із `LINE_PATH_TEST`), `STATION_STORE_TEST`, `SETTINGS_TEST`, тест плеєра (прапорці групи `AUDIO_PLAYER_*`), `DISPLAY_DEMO` (тестовий кадр дисплея). Режими, що користуються Serial (`LINE_PATH_TEST`, `STATION_STORE_TEST`, `SETTINGS_TEST`), ділять один порт, тому одночасно їх вмикати не слід. У релізній збірці всі тестові й діагностичні прапорці мають бути вимкнені (`0`); зокрема `LINE_PATH_DIAG` у релізі = 0, і тоді весь діагностичний код не компілюється. Для розробки сторінок на ПК є `WEB_API_DEV_CORS` (у релізі 0).
